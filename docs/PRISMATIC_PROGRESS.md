Se descarga únicamente Space Grotesk desde Google Fonts oficial (136 676 bytes) y OFL.txt (4 495 bytes), bajo autorización de internet/recursos del usuario. Fuente: https://github.com/google/fonts/tree/main/ofl/spacegrotesk . Consulta técnica: https://threejs.org/docs/pages/MeshPhysicalMaterial.html . No se incorpora ninguna fotografía ajena ni se modifica media/assets/.
- Limitaciones: transmisión rasterizada de Three.js, sin path tracing ni caústicas físicas completas. La lente de apertura refracta la escena 3D, no texto ni DOM superpuesto. SVG/backdrop-filter depende del motor y conserva borde/contraste de respaldo. El modelo 3D no sustituye una foto comercial exacta. Otros motores, hardware físico, recuperación de contexto, JS desactivado y pulido móvil específico quedan pendientes; el alcance solicitado es PC. Se conserva reflow básico.
- Archivos de esta revisión: templates/tiendaApp/{inicio,_mini_cd}.html; static/css/prismatic/landing.css; static/js/prismatic/{entry,mini-cd}.js; static/js/prismatic/landing/{stage,RoundedBoxGeometry}.js; static/js/prismatic/optical/{hero,gem-shader}.js; static/fonts/landing/{SpaceGrotesk.ttf,OFL.txt}; este documento.
- Vista local: http://127.0.0.1:8003/#mini-cd . Servidor WSGI de revisión en loopback con StaticFilesHandler; no ejecuta migraciones ni runserver con autoreload. Para el desarrollo normal se puede utilizar el arranque Django existente del proyecto y abrir /#mini-cd. Sin backend, MySQL, commit, push ni apagado programado.

Corrección del ciclo de efectos: la prueba repetida detectó un error de inicialización al reutilizar inmediatamente un canvas cuyo contexto se había perdido mediante forceContextLoss. Se elimina esa pérdida forzada; dispose sigue liberando geometrías, materiales, texturas y render targets, y el siguiente renderer reutiliza el contexto vivo del canvas. Se repite el modo completo/reducido en una pestaña limpia antes de entregar.

QA del arreglo de contexto: pestaña limpia, dos ciclos completo → reducido → completo sin recargar; stageReady=true tras ambos, cero errores/advertencias. Muestra final ~144,1 FPS y CPU ~0,50 ms, 1265×592. Vista final conservada en el navegador; captura local vinlume-landing-studio-final.jpg en la carpeta de visualizaciones de esta sesión.
